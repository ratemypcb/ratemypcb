## Trust Boundaries

| Boundary | Description |
| ---------- | ------------- |
| Golden JSON → evaluator | A permissive evaluator can bless ambiguous or dishonest reports |
| Active schema/version → skill consumer | Drift can make the skill parse or claim the wrong contract |
| Large summary fixture → report surface | Excess data can hide the decision and first action |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| ----------- | ---------- | ----------- | ---------- | ------------- | ----------------- |
| T-01-01 | Tampering | mutation evaluator | high | mitigate | One isolated mutation per named test with a valid control golden |
| T-01-02 | Repudiation | evidence refs/IDs | high | mitigate | Reject duplicate IDs and every unresolved assessment reference |
| T-01-03 | Information disclosure | golden fixtures | medium | mitigate | Purpose-built data only; no credentials, provider payloads, or third-party designs |
| T-01-04 | Denial of service / elevation | information overload and false approval | high | mitigate | Structural top-action/landmark/completeness limits and fail-closed state mutations |
| T-01-05 | Spoofing | schema/version drift | high | mitigate | Regression reads active core/schema/viewer/skill/reference version declarations |
| T-01-SC | Tampering | package installs | low | accept | Node and Rust standard test harnesses only; no install task |
